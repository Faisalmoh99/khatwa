# سجل التقدم (التطبيق الجديد في web/)

كل مرحلة: lint + test + build + e2e ناجحة، لقطات iPhone في `web/e2e/__screenshots__/`، commit، push، CI أخضر.

---

## المرحلة 0: الأساس وطبقة البيانات ✅ (8 نوفمبر)
- Vite + React + TypeScript strict + Tailwind، نظام تصميم في ملف واحد (`web/src/styles/tokens.css`).
- `rules.ts` نسخة مطابقة لـ `rules.js` (اختبار تطابق) + الاختبارات الـ13 + اختبارات R10.
- ثلاث مصادر بيانات خلف واجهة واحدة (Firebase / محاكاة / USB).
- **معيار القبول المتحقق:** المحاكي القديم `/sim/` يكتب في Firebase والتطبيق الجديد يعرضه مباشرة.

## المرحلة 1: مسار المريض الأساسي ✅ (8 نوفمبر)
**الشاشات:** الشعار، الافتتاحية (3)، الموافقة والخصوصية، الدخول التجريبي (جوال + 1234)، اختيار الدور، الرئيسية، الفحص الحي، النتيجة، الفحص السريع، جهازي، الإعدادات، المزيد.

**معايير القبول (كلها متحققة باختبارات):**
| المعيار | الاختبار |
|---|---|
| ساخن يوم 1 = أصفر، يوم 2 (وضع العرض) = برتقالي، مع السبب بالعربي | `e2e/phase1.spec.ts` «hot day 1…» |
| رسائل الجودة الخمس: قدم وحدة، حركة، قدم مبللة، حساس معطّل، كل النقاط (خطأ وقوف) | `quality message: …` (5 اختبارات) |
| الفحص السريع «جرح» = أحمر + حدث `quickcheck` | محليًا (محاكاة) + `@firebase` على جهاز اختبار `khatwa-e2e` (كتابة وقراءة من Firebase) |
| زر واتساب يفتح `wa.me/966…` برسالة فيها المستوى والنقطة | `WhatsApp button…` |
| «جهازي» يتحول لغير متصل (60 ثانية بتوقيت السيرفر) | `isOnline` في `types.test.ts` (59 ث متصل، 60 ث لا) + `device screen…` |
| اختبارات Vitest لـ level وwhatsapp وdayWord | `level.test.ts`، `whatsapp.test.ts`، `format.test.ts`، `ladder.test.ts` |
| المحاكي القديم → Firebase → فحص حي → نتيجة في التطبيق الجديد | `@firebase legacy /sim/…` |

**الأرقام:** 115 اختبار وحدة، 18 اختبار e2e، 2 اختبار Firebase حقيقي، 13 اختبار القاعدة القديمة.

**قرارات اتخذتها:**
1. **الأحمر يظهر حتى أثناء وضع الإيقاف** (سفر/ضماد/تنويم) لو المريض أبلغ عن جرح أو علامة خطر. النموذج القديم كان يخفيه. اخترت الأحوط.
2. **رسالة «القراءة منخفضة، قدمك مبللة؟»** تظهر أثناء القياس لو متوسط الحرارة أقل من 26° بعد 5 ثوان. تنبيه فقط، ما يغيّر أي قرار. سببها: المحاكي في حالة «قدمان مبللتان» يعطي قراءة نهائية منطقية فما كانت تطلع رسالة.
3. **رسائل الجودة تبقى 3 ثوان** بعد ما تختفي من البث، عشان كبير السن يلحق يقرأها.
4. **في وضع العرض، فحوصات ESP32** (اللي ما فيها `demoDay`) تترقّم أيامًا متتالية من لحظة تفعيل الوضع. ما لمست `rules.ts`.
5. **السلّم يحسب اليوم الحالي «فائت» بعد وقت التذكير فقط** (الافتراضي 8 مساءً)، عشان ما ننبّه العائلة الصبح قبل ما يلحق المريض يقيس.
6. **زر واتساب يظهر فقط لو موافقة العائلة مفعّلة.** لو الرقم فاضي، يفتح واتساب ويختار المريض المحادثة بنفسه.
7. **حذفت من نصوص المساعد القديمة** أي إشارة لتحليل الصورة («لنقارنه بصورتك الأساسية») وأي زمن («15 ثانية»).
8. **المسارات محمية:** أي شاشة دور بدون إكمال الافتتاحية والموافقة والدخول ترجع للبداية. الرابط `?as=patient` يتخطّى البداية (للعرض والاختبارات).
9. **الكتابة تنتظر اكتمال الدخول المجهول** (اكتشفته اختبارات Firebase: الكتابة السريعة بعد التحميل كانت تنرفض).
