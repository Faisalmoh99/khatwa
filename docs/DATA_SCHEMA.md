# شكل البيانات (الإصدار 1، معتمد 7 نوفمبر 2026)

هذا العقد بين **ESP32** و**المحاكي** و**التطبيق**. أي تغيير هنا يتغيّر في الثلاثة مع بعض.

```
/devices/khatwa-01/
  status/        يكتبها الجهاز كل 10 ثواني (نبضة)
  live/          يكتبها الجهاز كل ثانية أثناء الوقوف، ومرة وحدة لما يرجع idle
  scans/<id>     قراءة كاملة واحدة لما يخلص الفحص بنجاح (push)
  events/<id>    أحداث من التطبيق: فحص سريع، علامة خطر، إقرار العائلة/العيادة
  calibration/   نتائج المعايرة (للتوثيق في README)
```

## ترتيب النقاط (ثابت في كل مكان)
| index | النقطة | id |
|---|---|---|
| 0 | الإبهام | hallux |
| 1 | رأس المشط الأول | mth1 |
| 2 | رأس المشط الخامس | mth5 |
| 3 | الكعب | heel |

`L` = القدم اليسرى (GPIO 4)، `R` = القدم اليمنى (GPIO 18). الفرق دائمًا `R − L` (موجب = اليمين أسخن).

## status
| الحقل | النوع | ملاحظة |
|---|---|---|
| online | bool | `true` وهو شغّال |
| lastSeen | ms (وقت السيرفر) | `{".sv":"timestamp"}` من ESP32 |
| firmware | string | مثل `"0.1.0"` أو `"sim-0.1.0"` |
| source | `"esp32"` \| `"sim"` | |
| rssi | int (اختياري) | قوة الواي فاي |

ESP32 ما يقدر يكتب «غير متصل» لما ينطفي، فالتطبيق يعتبره **غير متصل** إذا `lastSeen` أقدم من **60 ثانية**.

### قواعد مهمة
- **لا تكتب `null` داخل مصفوفة.** Firebase يحذف العناصر الفاضية ويرجع المصفوفة ككائن. الحساس المعطّل = `-127` (نفس قيمة مكتبة DallasTemperature).
- ESP32 **ما يكتب scan** إذا الوقوف غلط (قدم وحدة أو نزل قبل الانتهاء). يكتب `live.phase = "error"` بس.
- الحكم (أخضر/أصفر/برتقالي) يصير **في التطبيق** من `app/js/rules.js`، مو في الجهاز. الجهاز يقيس ويرسل فقط.

## الاستقرار (الجهاز والمحاكي بنفس المنطق)
- الوقوف: حساسي الكعب الاثنين فوق العتبة (تتحدد بعد التجربة، مبدئيًا ADC > 1800 للبدء و< 600 = نزل).
- الاستقرار: كل الحساسات الثمانية تغيّرها أقل من **0.1°م خلال آخر 5 ثواني**، وبعد 8 ثواني على الأقل.
- الحد الأقصى **90 ثانية**، بعدها يُكتب scan مع `stable: false` (التطبيق يرفضها ويطلب إعادة).

## events/<id> (يكتبها التطبيق)
| الحقل | ملاحظة |
|---|---|
| kind | `quickcheck` \| `redflag` \| `photo` \| `family_ack` \| `clinic_ack` \| `mode` \| `escalation` \| `booking` \| `reminder` \| `question` \| `message` |
| data | كائن حسب النوع، مثل `{skin:"wound", pain:true}` |
| day | مفتاح اليوم (`2026-11-12` أو `D3`) |
| ts | وقت السيرفر |

### أنواع الأحداث (أُضيفت للتطبيق الجديد في 8 نوفمبر، الجهاز ما يتأثر)
| kind | data | معناه |
|---|---|---|
| `escalation` | `{to: "patient"\|"family"\|"clinic", level: 1–4, reason, why}` | سجل التدقيق: تنبيه راح لمين ومتى وليش |
| `mode` | `{mode: "travel"\|"bandage"\|"hospital"\|"normal"}` | أوضاع الإيقاف |
| `booking` | `{date, slot, note}` | طلب موعد (تجريبي) |
| `reminder` | `{time: "20:00"}` | ضبط التذكير اليومي |
| `question` | `{text}` | سؤال طبي حوّله المساعد للعيادة بدون إجابة |
| `message` | `{text}` | رسالة حرة محفوظة للعيادة |

النص اللي يجي من `data` يُعرض في التطبيق **كنص فقط**، أبدًا كـ HTML.

## photos/<id> (يكتبها التطبيق)
| الحقل | ملاحظة |
|---|---|
| role | `"base"` \| `"today"` |
| site | `{foot: "L"\|"R", i: 0–3}` (اختياري: المكان المنبّه عليه) |
| jpeg | صورة مصغّرة base64 (≤ 60KB) |
| day | مفتاح اليوم |
| ts | وقت السيرفر |

الصورة للعيادة تشوفها فقط. **ما فيه أي تحليل ولا مؤشر ولا مستوى من الصورة** (إصدار قادم).

## سطر USB (Web Serial، 115200)
احتياط لو النت خرب. ESP32 يطبع سطر JSON واحد لكل قراءة، بنفس شكل `live`:
```
{"L":[30.8,31.2,30.6,29.9],"R":[30.9,33.8,30.8,29.9],"fsrL":2610,"fsrR":2540}
```
- التطبيق يحسب الوقوف والاستقرار بنفس القواعد تحت (`web/src/data/stability.ts`).
- أي سطر ثاني (رسائل تشخيص مثل `WiFi connected`) يتجاهله التطبيق.
- الحساس المعطّل `-127` مثل Firebase.

## calibration
```
calibration/
  calibratedAt: ms
  reference: "Beurer FT09"
  waterC: 36.4
  sensors/
    "28FF64A1B2C3D4E5": { slot: "L0", rawC: 36.1, offsetC: 0.3 }
```
القيم نفسها تُكتب كثوابت في كود ESP32 (`calibration.h`). المسار هذا للتوثيق ونتائج الاختبار.

## قواعد الحماية (منشورة 8 نوفمبر، `firebase/database.rules.json`)
| المسار | مين يكتب | ملاحظة |
|---|---|---|
| `status`, `live`, `calibration` | حساب الجهاز فقط (`device-khatwa01@khatwa.app`) | ESP32 والمحاكي `/sim/` يدخلون بهذا الحساب |
| `scans/<id>` | حساب الجهاز فقط، **إضافة فقط** | لا تعديل ولا حذف، حتى من الجهاز |
| `events/<id>`, `photos/<id>` | أي مستخدم مسجّل دخول (التطبيق، دخول مجهول)، **إضافة فقط** | لا تعديل ولا حذف |
| القراءة | أي مستخدم مسجّل دخول | |

- كل حقل يتحقق من نوعه: L وR أربع أرقام بالضبط، `stable` و`standingOk` مطلوبة، `phase` و`kind` من القوائم فوق، الصورة JPEG أقل من 90 ألف حرف.
- **أي حقل ما هو مذكور في هذا الملف ينرفض.** لو أضفتوا حقل جديد في الجهاز، لازم يتضاف في القواعد وهنا مع بعض.
- رقم الجهاز لازم يبدأ بـ `khatwa-` (مثل `khatwa-01` أو `khatwa-test`).
- الاختبارات: `cd web && npm run test:rules` (14 حالة على المحاكي المحلي). النشر: `firebase deploy --only database`.
