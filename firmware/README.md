# كود السجادة (ESP32)

كل السكتشات هنا **تترجم بدون أخطاء** للوحة `ESP32 Dev Module` (اتجرّبت بـ `arduino-cli`). والجهاز يكتب في Firebase **نفس الحقول بالضبط** اللي في `docs/DATA_SCHEMA.md`، واتجرّب هذا على قواعد الحماية الحقيقية (على المحاكي المحلي).

> الجهاز **يقيس ويرسل بس**. ما يحسب القاعدة (أخضر، أصفر، برتقالي). القرار في التطبيق.

## 1) التوصيل

| من | إلى رجل ESP32 | ملاحظة |
|---|---|---|
| حساسات القدم **اليسرى** (4 × DS18B20) | **GPIO 4** | الأصفر = بيانات، الأحمر = 3.3V، الأسود = GND. مقاومة 4.7 إلى 5.1 كيلو بين الأصفر و3.3V (وحدة لكل خط) |
| حساسات القدم **اليمنى** (4 × DS18B20) | **GPIO 18** | نفس الشي |
| ضغط الكعب **الأيسر** | **GPIO 34** | مقسم جهد: الحساس من 3.3V، ومقاومة 10 كيلو إلى GND |
| ضغط الكعب **الأيمن** | **GPIO 35** | نفس الشي |
| LED **أخضر** | **GPIO 25** | عبر مقاومة 220 أوم إلى GND |
| LED **أحمر** | **GPIO 26** | عبر مقاومة 220 أوم إلى GND |
| **البازر** (active) | **GPIO 27** | الطرف الثاني إلى GND |

**ترتيب النقاط في كل قدم (ثابت في كل مكان):** إبهام، رأس المشط الأول، رأس المشط الخامس، كعب.

## 2) التجهيز مرة وحدة

**الطريقة الأسهل: Arduino IDE**
1. Preferences ← Additional boards URLs: `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. Boards Manager ← `esp32` من Espressif ← Install.
3. Library Manager ← ثبّت: `OneWire` و`DallasTemperature` و`FirebaseClient` (من mobizt).
4. Tools ← Board ← **ESP32 Dev Module**. وTools ← Port ← المنفذ اللي يطلع لما توصل الكابل.

**أو بالطرفية (`arduino-cli`، مثبّت على جهازك):**
```bash
arduino-cli board list                                    # يطلع لك المنفذ، مثل /dev/cu.usbserial-0001
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/01_blink
arduino-cli upload  --fqbn esp32:esp32:esp32 -p /dev/cu.usbserial-0001 firmware/01_blink
arduino-cli monitor -p /dev/cu.usbserial-0001 -c baudrate=115200
```

**الأسرار:** ملف `khatwa_esp32/secrets.h` موجود ومعبّى عندك، وما يترفع لـ GitHub. لو احتجت تعيده، انسخ `secrets.example.h`.

## 3) خطوات بكرة بالترتيب

في كل خطوة: ارفع السكتش، وافتح **Serial Monitor على 115200**.

| الخطوة | السكتش | وش تسوي | وش يطلع على الشاشة | وش يعني النجاح |
|---|---|---|---|---|
| 1 | `01_blink` | وصّل الـESP32 بس | `# blink ON` و`# blink OFF` كل نص ثانية | الضوء الأزرق على اللوحة والأخضر يومضون |
| 2 | `02_one_sensor` | حساس واحد على GPIO 4 + المقاومة | `# found 1 sensor(s)` ثم `# temperature: 26.40 C` | امسك الحساس بيدك: الرقم يرتفع |
| 3 | `03_scan_addresses` | الأربعة يسار على 4، والأربعة يمين على 18 | قائمة عناوين مثل `{0x28, 0xFF, ...},` ثم حرارة كل حساس كل ثانيتين | `4 sensor(s)` لكل قدم. **المس كل حساس** وشوف أي سطر يسخن، وانسخ عنوانه في `config.h` في مكانه (إبهام، مشط أول، مشط خامس، كعب) |
| 4 | `04_fsr` | حساسي الضغط | `# fsrL=  85  fsrR=  70  -> EMPTY` | قف على السجادة: الرقمين فوق 1800 وتطلع `STANDING`. انزل: تحت 600. لو أرقامك مختلفة، عدّل `FSR_ON` و`FSR_MIN` في `config.h` |
| 5 | `05_leds_buzzer` | الضوءين والبازر | `# measuring` ثم `# saved` ثم `# rejected` | أخضر يومض، ثم أخضر + صفارة، ثم أحمر + صفارتين |
| 6 | `khatwa_esp32` | الكامل | انظر تحت | قراءة تظهر في التطبيق |

### الكامل (`khatwa_esp32`)
قبل ما ترفعه: عبّي جدول العناوين `ROM_L` و`ROM_R` في `config.h` من الخطوة 3 (لو تركته أصفار، الكود يشتغل بترتيب السلك ويطبع تحذير).

**وش يطلع على الشاشة:**
```
# Khatwa firmware 0.2.0, device khatwa-01
# LEFT foot: 4 sensor(s) on the wire
# RIGHT foot: 4 sensor(s) on the wire
# Wi-Fi: 192.168.1.23
# auth: ...
{"L":[26.10,26.30,26.00,25.80],"R":[26.20,26.30,26.10,25.90],"fsrL":80,"fsrR":75}
# standing: measuring
{"L":[30.80,31.20,30.60,29.90],"R":[30.90,33.80,30.80,29.90],"fsrL":2600,"fsrR":2550}
# scan ready: stable=1 rejected=0 faults=0 (14s)
# scan saved
```
- الأسطر اللي تبدأ بـ `#` للشرح. الأسطر اللي تبدأ بـ `{` هي **جسر USB** (التطبيق يقرأها لو اخترت «كابل USB» في الإعدادات).
- **الأضواء:** أخضر يومض = يقيس. أخضر ثابت + صفارة = القراءة انحفظت. أحمر + صفارتين = القراءة مرفوضة (قدم وحدة، نزل بدري، ما استقرت خلال 90 ثانية، أو حرارة غير منطقية).
- بعد أول قراءة، تأكد من الشكل في Firebase:
  ```bash
  cd web && npm run check:device
  ```

**وش يسوي الكود بالتفصيل:**
- **الوقوف:** الكعبين فوق `FSR_ON`. لو كعب واحد بس لمدة 3 ثوان، أحمر («قدم وحدة»). لو نزل قبل الانتهاء، أحمر وما ينكتب شي.
- **الاستقرار:** كل الحساسات الثمانية تتغير أقل من 0.1° خلال 5 ثوان، وبعد 8 ثوان على الأقل. لو وصل 90 ثانية بدون استقرار، ينكتب scan مع `stable:false` (التطبيق يرفضه ويطلب إعادة).
- **الحساس المعطّل:** `-127` (منفصل) و`85` (قراءة قبل ما تخلص) ينكتبون `-127`، ونقطتهم بدون مقارنة، والباقي يكمّل عادي.
- **Firebase:** `status` كل 10 ثوان (وقت السيرفر)، و`live` كل ثانية وقت الوقوف ومرة لما يرجع فاضي، و`scan` عند الاستقرار أو الحد الأقصى.
- **لو النت انقطع:** يكمّل يقيس ويطبع على USB، ويحفظ لين 10 قراءات في الذاكرة ويرسلها لما يرجع النت (بوقتها الحقيقي من NTP). ويعيد محاولة الواي فاي كل 10 ثوان، بس **مو وقت ما أحد واقف**.
- **شبكتين واي فاي:** `WIFI_SSID` و`WIFI_SSID_2` في `secrets.h`. يتصل بالأقوى المتوفر.
- **المعايرة:** `OFFSET_L` و`OFFSET_R` في `config.h` (صفر الحين). بعد اختبار الماء، حط الفرق لكل حساس.

## 4) لو ما اشتغل

| المشكلة | الحل |
|---|---|
| المنفذ ما يطلع | جرّب كابل ثاني (بعض الكابلات شحن بس). لو ما زال، ثبّت تعريف CH340 أو CP2102 حسب الشريحة المكتوبة على اللوحة |
| الرفع يعلق عند `Connecting....` | اضغط زر **BOOT** على اللوحة لين يبدأ الرفع |
| الحرارة `-127` | السلك الأصفر مو على الرجل الصح، أو المقاومة ناقصة، أو الحساس مقلوب (أحمر وأسود) |
| الحرارة `85` دايمًا | الحساس ما ياخذ كهرباء كافية. تأكد من 3.3V والأرضي |
| أقل من 4 حساسات في الخطوة 3 | حساس منفصل. افحص الوصلات واحد واحد |
| الضغط دايمًا 0 أو 4095 | مقسم الجهد ناقص: لازم مقاومة 10 كيلو بين الرجل والـ GND |
| `# Wi-Fi: not connected` | ESP32 يشوف 2.4GHz بس. في الآيفون: فعّل Maximize Compatibility |
| `# auth error` | كلمة مرور حساب الجهاز غلط في `secrets.h`، أو الحساب ما هو مفعّل في Firebase |
| `# scan not sent (PERMISSION_DENIED)` | فيه حقل زيادة أو ناقص. لا تعدّل `khatwa_json.h` بدون ما تعدّل `docs/DATA_SCHEMA.md` والقواعد مع بعض |
| الأضواء ما تشتغل | الطرف الطويل للـLED على الرجل، والقصير على المقاومة ثم GND |

## 5) للمطوّر: الاختبارات
- **منطق الاستقرار والجودة** في `khatwa_esp32/khatwa_core.h`، و**بناء JSON** في `khatwa_json.h`. الاثنين بدون مكتبات Arduino، ويتجرّبون على الماك:
  ```bash
  cd firmware/test && g++ -std=c++17 -I../khatwa_esp32 test_core.cpp -o /tmp/test_core && /tmp/test_core
  ```
  الحالات: وقوف مستقر، حركة، حساس `-127` و`85`، تجاوز 90 ثانية، قدم وحدة، نزول بدري، قدم مبللة، وشكل الـJSON.
- **مطابقة الشكل:** `web/src/data/firmware.test.ts` يولّد JSON من نفس الدوال ويمرّره على مخططات zod الصارمة في التطبيق (ضمن `npm test`). و`npm run test:rules` (الحالة 15) يكتبه على قواعد Firebase في المحاكي المحلي.
- **الترجمة:** `arduino-cli compile --fqbn esp32:esp32:esp32 firmware/<السكتش>` لكل مجلد.
